# Research: post-management

## Research Question
How should the new `feature/post/` package mirror the existing `feature/user/` hexagonal architecture to implement post CRUD, media upload, soft-delete, feed pagination, and cross-feature integration?

## Summary
The `feature/post/` package must replicate the feature-first hexagonal structure established in `feature/user/`: ports in `api/`, package-private `PostService` implementing them, `PostController` wired only to ports, JPA entities with `@PrePersist`/`@Version`, MapStruct mappers, Flyway migrations, and local media storage adapter. Key cross-cutting concerns:

- `MediaStoragePort` needs a new `uploadPostMedia(MultipartFile)` method; existing `LocalMediaStorageAdapter` must implement it and handle `/post-media/` URL prefix in `delete()`
- `authorName` in `Post` is denormalized `externalId` from `UserDTO` (via `UserQueryPort.getProfile()`); `authorAvatarUrl` is **excluded entirely**
- Feed endpoint `GET /api/v1/users/{userId}/posts` lives in `PostController` with a full `@GetMapping` path, not in `UserController`
- Transaction rollback cleanup via `TransactionSynchronizationManager` must be replicated in `PostService` for media uploads
- Soft-delete is implemented via `deleted` boolean with `@Query` override on `PostRepository.findById()`

## Detailed Findings

### MediaStoragePort Evolution
- `src/main/java/lghdnov/msocial/feature/user/api/MediaStoragePort.java:13` — existing port defines `uploadAvatar`, `uploadTrack`, `delete`
- A new `uploadPostMedia(MultipartFile)` method must be added between `uploadTrack` (line 31) and `delete` (line 38)
- `src/main/java/lghdnov/msocial/feature/user/infrastructure/LocalMediaStorageAdapter.java:23` — must add `postMediaPath` field, `uploadPostMedia()` method, and update `delete()` to handle `/post-media/` prefix (currently binary `avatars`/`tracks` branch at line 60)
- `src/main/resources/application.yaml:35-37` — add `post-media-path: ${POST_MEDIA_STORAGE_PATH:./uploads/post-media}` under `app.storage.local`
- Adding a second adapter (`LocalPostMediaStorageAdapter`) implementing the same port creates `NoUniqueBeanDefinitionException`; every injection site must use `@Qualifier`
- `UserService.java:51` currently injects unqualified `MediaStoragePort`; must add `@Qualifier("localMediaStorageAdapter")`

### Author Snapshot (Denormalized)
- `UserQueryPort.java:14` — `getProfile(Long userId)` returns `UserDTO` with `externalId` field
- `UserService.java:80-86` — implementation loads `User` + `PersonalInfo`, maps via `UserMapper`

- `PostService` at creation time calls `userQueryPort.getProfile(authorId)` and stores `userDTO.externalId()` as `authorName`
- `authorAvatarUrl` is **excluded** from `Post` entity, `PostDTO`, Flyway migration, and all API contracts

### Controller Pattern
- `UserController.java:22-31` — `@RestController @RequestMapping("/api/v1/users")`, constructor-injects `UserQueryPort` + `UserCommandPort`
- `PostController` mirrors this: `@RestController @RequestMapping("/api/v1/posts")`, injects `PostQueryPort` + `PostCommandPort`
- Feed endpoint `GET /api/v1/users/{userId}/posts` is placed in `PostController` with full path `@GetMapping("/api/v1/users/{userId}/posts")` (developer decision: Variant B)
- `UserController.java:88-95` — `resolveUserId(Principal)` pattern with `AccessDeniedException` for null/malformed principal; mirrored in `PostController`

### Service Pattern
- `UserService.java:36` — package-private `@Service class UserService implements UserQueryPort, UserCommandPort, UserProvisioningPort`
- `PostService` mirrors: package-private `@Service class PostService implements PostQueryPort, PostCommandPort`
- `UserService.java:112-119` — upload flow: `mediaStoragePort.uploadAvatar(file)` then `registerRollbackCleanup(url)`
- `UserService.java:169-180` — `registerRollbackCleanup` uses `TransactionSynchronizationManager.registerSynchronization` to delete file on `STATUS_ROLLED_BACK`
- **Asymmetry found:** `UserService.uploadTrack()` (lines 137-154) calls `uploadTrack()` but **never registers rollback cleanup** — leaves orphaned files on rollback
- `PostService` must replicate the rollback pattern for both standalone media upload and full post creation transactions
- Authorization: `PostService` compares `post.getAuthorId()` against caller `userId`; mismatch → `throw new AccessDeniedException("NOT_AUTHOR", "...")`
- `GlobalExceptionHandler` (inferred from precedent analysis) catches `AccessDeniedException` and returns HTTP 403

### Entity & JPA Patterns
- `User.java:24-35` — `@Column(name = "created_at", nullable = false) Instant createdAt`; `@Version Long version`; `@PrePersist` initializes `createdAt`
- `Avatar.java:30-31, 38-40` — boolean `active` with `@Column(nullable = false)` and `@PrePersist` default `true`
- `Post` entity mirrors `User` for `createdAt`/`@Version`/`@PrePersist`, plus `deleted` boolean (default `false` in `@PrePersist`, mirroring `Avatar.active` pattern)
- `PostMedia` entity carries only `@Version` (no timestamp), mirroring `PersonalInfo.java:36-37`
- `PostRepository` extends `JpaRepository<Post, Long>` and overrides `findById` with `@Query("SELECT p FROM Post p WHERE p.id = ?1 AND p.deleted = false")`
- `PostRepository` adds `Page<Post> findAllByAuthorId(Long authorId, Pageable pageable)` with same soft-delete filter

### MapStruct Mapper Pattern
- `UserMapper.java:14-28` — `@Mapper(componentModel = MappingConstants.ComponentModel.SPRING)`, multi-source `@Mapping`, nested collection delegation
- `PostMapper` at `feature/post/presentation/mapper/PostMapper.java` mirrors: multi-source `toDto(Post post, List<PostMedia> media)`, nested `PostMediaDTO toDto(PostMedia)`, explicit `List<PostMediaDTO> toDtoList(List<PostMedia>)`
- `UserDTO.java:8-18` / `AvatarDTO.java:8-16` — `record` DTOs with `@Schema(description=..., example=...)`; `PostDTO` and `PostMediaDTO` follow same convention

### Flyway Migration
- `V2__create_users_and_profiles.sql:1-23` — canonical style: `BIGSERIAL PRIMARY KEY`, `TIMESTAMP WITH TIME ZONE NOT NULL`, `version BIGINT DEFAULT 0`, explicit FK constraints, targeted indexes
- `V4__create_posts_and_post_media.sql` must create:
  - `posts` table: `id`, `author_id BIGINT NOT NULL`, `author_name VARCHAR(255) NOT NULL`, `content VARCHAR(5000) NOT NULL`, `deleted BOOLEAN NOT NULL DEFAULT false`, `created_at TIMESTAMP WITH TIME ZONE NOT NULL`, `version BIGINT DEFAULT 0`, FK to `users(id)`
  - `post_media` table: `id`, `post_id BIGINT NOT NULL`, `url VARCHAR(500) NOT NULL`, `sort_order INTEGER NOT NULL`, `version BIGINT DEFAULT 0`, FK to `posts(id)`
  - Indexes: `idx_posts_author_id`, `idx_posts_created_at DESC` (or composite `author_id, created_at DESC`), `idx_post_media_post_id`
- `application.yaml:10` — `ddl-auto: validate` requires 1:1 alignment between DDL and JPA annotations

## Architecture Insights
- **Cross-feature port extension is cascading:** Adding `uploadPostMedia` to `MediaStoragePort` forces every adapter and every injection site to update. Using `@Qualifier` is mandatory once a second adapter exists.
- **Denormalized snapshot avoids read-time cross-feature calls:** `authorName` (=`externalId`) is captured once at post creation; `GET /api/v1/posts/{id}` reads purely from `Post` table.
- **Soft-delete at repository level is cleaner than service-level filtering:** Overriding `findById` with `@Query` ensures all callers (service, future features) automatically respect soft-delete without defensive `if (post.isDeleted())` checks.
- **Rollback cleanup belongs in service, not adapter:** `TransactionSynchronizationManager` is an application-layer concern. The adapter only implements `delete(String url)`.
- **Feed endpoint in `PostController` preserves feature boundaries:** Even though the URL starts with `/api/v1/users/`, placing it in `feature/post/` keeps all post logic inside the post feature, avoiding `UserController` importing `PostQueryPort`.

### Composite Lessons
- **#1:** Architecture violations are the most common follow-up fix — both `auth` and `user` needed immediate repair commits. Top errors: services importing infrastructure directly, controllers lacking input validation, cross-feature entity leakage through port signatures.
- **#2:** Media upload requires transaction rollback cleanup — `feature/user` added it retroactively; `feature/post` must implement it upfront.
- **#3:** Port interfaces need complete contracts upfront — Auth ports were missing methods that caused follow-up fixes. Design `PostQueryPort`/`PostCommandPort` with full CRUD + pagination from the start.
- **#4:** Principal resolution needs centralized validation — `UserController` originally did `Long.valueOf(principal.getName())` inline; fix extracted `resolveUserId` with null/format checks. Mirror this pattern immediately.
- **#5:** SecurityConfig must permit Swagger paths — `99c20c7` added `/swagger-ui/**` and `/v3/api-docs/**` to `permitAll()`. Post endpoints must be explicitly configured.
- **#6:** Flyway + `ddl-auto=validate` means zero tolerance for schema drift. `V4` must exactly match `Post`/`PostMedia` annotations or app fails on startup.
- **#7:** Test coverage pattern: unit tests for every layer — `feature/user` shipped with controller, service, repository, validator, and adapter tests. Post should replicate this 5-layer test matrix.
